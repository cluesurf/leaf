# `@cluesurf/bead`. Design notes

Spec docs for the bead runtime, schema vocabulary, and codegen
pipeline. Living docs — refine in place as decisions firm up.

## Canonical naming

- **`Book`** — type. A published bundle of Forms / Flows /
  Folds / Hashes / Lists with optional `host` + `name`
  metadata. Plain data; compose with object spreads.
- **`Code`** — type. The colon-keyed registry mapping every
  entry to its TypeScript type. Generated by `Make.save()`.
- **`Base`** — class. The runtime that registers flow handlers
  and dispatches calls. Generic over `Code`.
- **`Make`** — class. The codegen orchestrator that walks
  registered Books and emits artifacts.

## End-to-end flow today

```
authored declarations           runtime registration
─────────────────────           ────────────────────
code/base/<verb>/make.ts        new Base<Code>()
code/base/<verb>/flow.ts        base.load(standard)

           ↓                           ↓

      Make.save()                 base.call('is',
                                    { base: 'ipa',
                                      case: 'broad',
                                      text: 'foo' })
           ↓
   code/base/code.ts
   (generated Code type)
```

`pnpm make:base` runs `task/save.ts` → invokes `Make.save()`
→ writes `code/base/code.ts`. Authoring a new flow is three
edits: declare in the verb's `make.ts`, implement in the
verb's `flow.ts`, run `pnpm make:base`.

## What remains

### Codegen

- **Numeric-id call rewrite.** Per spec, codegen rewrites
  `base.call('is', { base: 'ipa', case: 'broad', text: 'foo' })`
  → `base.call(123, { text: 'foo' })` for fast dispatch. The
  runtime supports the numeric overload; no codegen pass yet
  emits the rewrites or the integer-id table.
- **Zod parser generation from new shapes.** The legacy
  codegen pipeline emits Zod parsers from the old form-DSL
  fixtures. The new `Make.save()` only emits the `Code` type;
  it should also emit `parsers.ts` for runtime input
  validation via `base.call()`.
- **Native read of new schemas.** The codegen pipeline
  (`code/make/{base,form,take}.ts`) still reads legacy
  fields — kept compiling via `@internal` optional fields on
  `Form` / `Link` / etc. Eventually rewrite to read the
  simplified spec fields directly, then drop the legacy
  shims.
- **String-ref resolution in Flow `take`/`make`.** Today,
  unresolved string refs (e.g., `take: 'language_request'`)
  fall back to `unknown` in the generated Code. Codegen
  should resolve them to the matching named Form's TS type.

### Catalog

- **Remaining verbs**: `find` (async lookups), `walk`
  (4-variant iteration), `if` (conditional), `validate`
  (error-collecting wrapper), `bind` (let-bindings). Each
  has richer semantics than the simple predicate / transform
  pattern the current verbs use.
- **Cross-verb compositions** in `catalog.md`. Worked-example
  trees showing how the catalog flows compose.

### Runtime

- **Async batching for `find:*` flows.** Spec describes a
  pre-resolution pass that batches every `async: true` flow
  call. Not implemented.
- **`base.cast(tree, scope?)` evaluator.** Compile + execute
  an editable tree. Spec is in `runtime.md`; current `Base`
  class only does per-flow `call()`.
- **Real-time partial recompilation** (`base.bindPatch`).
  For the editor's hot path. Tier-based validation.
- **Recursion + let-binding via `bind` flow.** Once the
  `bind` catalog verb lands.

### Editor

- **Patch protocol** (`TreePatch`, `BindResult`,
  `RenderDiff`). Types not yet in code; spec is in
  `editor.md`.

### Migration

- **Legacy fixtures** in `test/form.ts` and `test/hold/*` use
  old form-DSL field shapes. Tests pass via the `@internal`
  legacy fields. Cleanup task: rewrite to new shapes, then
  drop those fields entirely.
- **Codegen-script stubs.** `code/base/codegen-script.ts`
  and `code/base/save.ts` are empty `export {}` placeholders
  (couldn't `rm` from the agent shell). Delete them
  manually. The active script lives at `task/save.ts`.

### Spec gaps (documented in codegen-questions.md)

- Cross-Book reference resolution (when a Form in Book A
  references a Form in Book B).
- Generic Flow type derivation (`head: ['t']` parameters).
- Async Flow return-type derivation.
- Multi-runtime interop contract.
